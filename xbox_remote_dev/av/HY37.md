# HY37 receive-side wire contract

Observed in the user-provided PC-PERFORMER-AV-v38.py. These are protocol
facts, not a license or an Xbox capture API. TCP is Xbox -> PC port 36000;
control bytes travel back on the same connection. This protocol is separate
from XBDM TCP 730 and the future remote input protocol.

All header integers are big endian. Header size is 28 bytes, equivalent to
Python `struct` format `>IBBHHHIIII`.

| Offset | Size | Field |
| --- | --- | --- |
| 0 | 4 | Magic `0x48593337` (`HY37`) |
| 4 | 1 | Codec: 0 status, 1 JPEG, 2 I420, 3 PCM |
| 5 | 1 | Mode |
| 6 | 2 | Video width; audio channels |
| 8 | 2 | Video height; audio bits/sample |
| 10 | 2 | JPEG quality; audio sample rate |
| 12 | 4 | Payload byte count |
| 16 | 4 | Video sequence; audio-specific sequence |
| 20 | 4 | Video capture microseconds; audio driver ID |
| 24 | 4 | Video encode microseconds |

Payloads must be complete before decode/playback. The receiver caps payloads
at 2 MiB, statuses at 4096 bytes, video at 1920x1080, and PCM at one second
per packet. I420 requires even dimensions and exactly width*height*3/2 bytes
(Y, U, V planes). It uses BT.601 limited-range conversion. JPEG SOI/EOI and
SOF dimensions must match the header before image decode.

PCM is interleaved stereo, unsigned 8-bit or signed little-endian 16-bit,
at 12000/24000/44100/48000 Hz. Packet size must align with stereo samples.
The Windows playback queue allows four buffers with a 100 ms total budget;
overlarge packets keep their final 100 ms, and queued overflow is dropped.
Trimming/drops are reported separately from received complete audio packets.
The first audio driver is selected initially; the user can cycle driver IDs.

Used control bytes from the observed viewer:

| Control | Meaning exposed by original viewer |
| --- | --- |
| `@640,360,45,1,4,10,0,0\n` | Request 640x360, Q45, 1 worker, capture C4, 10 FPS, 4:2:0, one pass |
| `@640,480,45,1,4,10,0,0\n` | Same request at 640x480 |
| `J` / `K` | Enable / disable audio |
| `L` / `S` / `M` / `N` | Request 48000 / 44100 / 24000 / 12000 Hz |
| `O` / `P` | Request 16 / 8-bit PCM |
| `X` | Request preparation for module unload |

Requests are not acknowledgement that the settings were applied. Inspect
received frame/audio fields and actual counts. A status packet with exact
ASCII `SAFE_TO_UNLOAD` is accepted as a module acknowledgement only after an
explicit `X` in the same session. A new session resets it. EOF, timeout and
other statuses never create this acknowledgement. The acknowledgement cannot
prove that a closed-source module restored every hook safely.

There is no verified authentication, shared AV presentation clock, or controller
input in this interface. Bind a specific trusted LAN address, limit the peer,
and do not forward this port or XBDM to the Internet.
